# SPEC-NNN — <Nombre de la capacidad>

| Campo           | Valor                                            |
| --------------- | ------------------------------------------------ |
| **Estado**      | borrador \| aprobada \| implementada \| retirada |
| **Componentes** | `src/components/…`                               |
| **Datos**       | `landing.data.ts` → `…`                          |
| **Ancla**       | `#…` (o «—» si la sección no tiene)              |
| **Depende de**  | SPEC-NNN, … (o «—»)                              |

## Propósito

Una o dos frases: qué consigue el visitante gracias a esta capacidad y por qué existe.
Sin detalles de implementación.

## Actores

Quién interactúa y qué espera de ella.

## Requisitos funcionales

Numerados y estables. Presente, afirmativo, observable. Un requisito retirado se marca
`(retirado)`; no se renumera ni se reutiliza su número.

- **RF-01** — …
- **RF-02** — …

## Reglas de contenido

Qué datos alimentan la sección, sus restricciones (cantidad, longitud, formato) y qué
ocurre en los casos límite (lista vacía, campo opcional ausente).

## Comportamiento visual

Disposición, puntos de ruptura responsive y animaciones. Solo lo que es intencional y
debe conservarse.

## Criterios de aceptación

Verificables a mano, en formato Dado / Cuando / Entonces.

- **CA-01** — Dado … cuando … entonces …
- **CA-02** — …

## Fuera de alcance

Qué NO hace esta capacidad, sobre todo lo que alguien podría suponer que sí.

## Deuda conocida

Limitaciones aceptadas hoy, con la condición que las resolvería. Omitir la sección si no
hay ninguna.
